# campus-bookstore-qa

학과 중고책 거래 서비스를 대상으로 한 **QA 포트폴리오 저장소**입니다.
요구사항 분석부터 테스트 설계, 수동 테스트, SQL·API 검증, Playwright 자동화, Jenkins CI까지 한 서비스에서 이어지는 QA 과정을 기록합니다.

## 현재 상태

| 영역 | 상태 |
|---|---|
| 요구사항 검토·테스트 설계 | 로그인 기능 설계 초안 작성 (TC 3개, 인수조건 4개, 확인 질문 5개) |
| 수동 테스트 실행 | 아직 없음 (실행 환경 확보 전, 모든 TC `Not Run`) |
| SQL·API 검증 | 예정 |
| UI 자동화 (Playwright) | 예정 |
| CI (Jenkins)·리포트 (Allure) | 예정 |

## 문서

- [로그인 테스트 설계 초안](docs/login-test-design.md)

## 기록 원칙

- 실행하지 않은 테스트는 `Not Run`으로 표시하고, 실행 결과로 기록하지 않습니다.
- 실제로 발견하지 않은 결함은 기록하지 않습니다. 학습을 위해 일부러 넣은 결함은 따로 표시합니다.
- 요구사항(R) → 테스트 케이스(TC) → 실행 기록 → 결함(BUG) → 자동화(AUTO)를 ID로 연결합니다.
- AI는 리뷰와 문서 정리에 활용하며, 각 문서에 본인 작성 부분을 구분해 표시합니다.
