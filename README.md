# 중고책 거래 서비스 QA — 로그인 테스트 설계 초안

- 작성: 2026-09-28 ~ 2026-09-29
- 상태: 학습용 가상 요구사항을 기준으로 한 **설계 문서**입니다. 실제 서비스에서는 아직 실행하지 않았으므로 모든 TC는 `Not Run`입니다.
- 작성 기여: TC-LOGIN-002~004, 확인 질문, 확인 증거, 인수조건(AC-LOGIN-03-PASSWORD, AC-LOGIN-04-FORMAT), 위험 평가는 본인이 작성했습니다. AI는 리뷰와 표현 정리, 문서화를 도왔습니다. "강의 예시"로 표시한 항목은 본인 작성 실적에 포함하지 않습니다.

## 1. 범위

로그인 기능 중 실패 처리와 필수값 검증을 다룹니다. API 명세, 실제 사이트, 실행 환경은 아직 확인하지 않았습니다.

## 2. 학습용 요구사항

실제 서비스의 확정 정책이 아니라 수업을 위해 정한 요구사항입니다.

| ID | 내용 |
|---|---|
| R-LOGIN-01 | 가입 완료·활성 계정의 올바른 이메일과 비밀번호로 로그인하면 책 목록으로 이동하고 해당 사용자 닉네임을 표시한다. |
| R-LOGIN-02 | 비밀번호가 틀리면 "이메일 또는 비밀번호를 확인해 주세요."를 표시하며 로그인되지 않는다. |
| R-LOGIN-03 | 이메일 또는 비밀번호가 빈 값이면 로그인 요청을 서버로 보내지 않고 누락된 항목 안내를 표시한다. |
| H-LOGIN-04 (가정) | `abc`처럼 `@`가 없는 값은 이메일 형식 오류로 처리한다. 형식 오류라면 이메일 형식 안내를 표시하고 로그인 요청을 보내지 않는다. 전체 이메일 형식 정책을 정의한 것은 아니다. |

## 3. 요구사항 확인 질문

아직 정해지지 않아 담당자에게 확인해야 하는 정책입니다. 모두 미결정 상태입니다.

| ID | 질문 | 상태 |
|---|---|---|
| Q-LOGIN-01 | 이메일 형식이 잘못되면 로그인 요청 전에 차단하나요? 어떤 안내를 표시하고, 형식 판정 규칙은 무엇인가요? | 확인 필요 |
| Q-LOGIN-02 | 연결이 끊기거나 응답이 지연되면 어떤 안내를 표시하나요? 대기 시간과 재시도 정책은 무엇인가요? | 확인 필요 |
| Q-LOGIN-03 | 네트워크에 연결되지 않은 상태에서 로그인을 시도하면 어떤 안내와 재시도 방법을 제공하나요? | 확인 필요 |
| Q-LOGIN-04 | 로그인 요청 후 제한 시간 안에 응답을 받지 못하면 어떤 안내를 표시하나요? 제한 시간은 얼마인가요? | 확인 필요 |
| Q-LOGIN-05 | 응답은 받았지만 명세와 달라 해석할 수 없으면 어떻게 처리하나요? | 확인 필요 |

Q-LOGIN-04와 05는 "응답이 돌아오는 도중 문제가 생긴 경우"라는 질문을 관찰 가능한 두 상황으로 나눈 것입니다. 클라이언트가 실제 장애 위치를 항상 알 수 있다고 가정하지 않습니다.

## 5. 테스트 케이스

실제 테스트 계정과 비밀번호는 아직 배정하지 않았습니다.

### TC-LOGIN-002 — 틀린 비밀번호

| 항목 | 내용 |
|---|---|
| 요구사항 | R-LOGIN-02 |
| 사전조건 | 가입 완료·활성 학습용 계정 존재, 로그아웃 상태 |
| 입력 | 학습용 계정 이메일, 그 계정의 실제 비밀번호와 다른 값(다른 형식 검증은 통과) |
| 단계 | 로그인 화면 열기 → 이메일과 틀린 비밀번호 입력 → 로그인 클릭 |
| 기대 결과 | "이메일 또는 비밀번호를 확인해 주세요." 표시, 인증되지 않음 |
| 확인 증거 | 화면 문구, 명세 기준의 인증 실패 응답, 로그인이 필요한 기능을 실제로 실행하려 할 때 거부됨 |
| 실제 결과 | 미실행 |
| 상태 | Not Run |

### TC-LOGIN-003 — 이메일 빈 값

| 항목 | 내용 |
|---|---|
| 요구사항 | R-LOGIN-03 |
| 사전조건 | 로그아웃 상태, 로그인 화면 (필수값 검증만 볼 때는 활성 계정이 꼭 필요하지 않음) |
| 입력 | 이메일 빈 문자열 `""`, 다른 검증을 통과하는 정상 비밀번호 값 |
| 단계 | 이메일이 비어 있음을 확인 → 비밀번호 입력 → 로그인 클릭 |
| 기대 결과 | 로그인 요청 미전송, 이메일 누락 안내 (정확한 문구는 확인 필요) |
| 확인 증거 | 이메일 누락 안내, 브라우저에서 로그인 요청이 발생하지 않음 |
| 실제 결과 | 미실행 |
| 상태 | Not Run |

### TC-LOGIN-004 — 비밀번호 빈 값

| 항목 | 내용 |
|---|---|
| 요구사항 | R-LOGIN-03 |
| 사전조건 | 로그아웃 상태, 로그인 화면 |
| 입력 | 정상 형식의 학습용 계정 이메일, 비밀번호 빈 문자열 `""` |
| 단계 | 이메일 입력 → 비밀번호가 비어 있음을 확인 → 로그인 클릭 |
| 기대 결과 | 로그인 요청 미전송, 비밀번호 누락 안내 (정확한 문구는 확인 필요) |
| 확인 증거 | 비밀번호 누락 안내, 브라우저에서 로그인 요청이 발생하지 않음 |
| 실제 결과 | 미실행 |
| 상태 | Not Run |

참고: 빈 문자열 `""`과 공백 `" "`은 다른 입력입니다. 공백만 입력한 값을 빈 값으로 처리할지는 아직 확인해야 하는 정책입니다.

## 6. 위험 평가와 테스트 실행 순서

발생 가능성(L)과 영향(I)은 수업에서 제공한 가정값이며 실제 통계가 아닙니다. 점수 계산과 순서·근거는 본인이 작성했습니다.

| 순서 | 위험 | L | I | 점수 (L×I) | 근거 |
|---|---|---|---|---|---|
| 1 | 정상 계정과 올바른 비밀번호로도 로그인 불가 | 2 | 3 | 6 | 점수가 가장 높고, 로그인이 필요한 기능을 쓸 수 없음 |
| 2 | 틀린 비밀번호로도 로그인 허용 | 1 | 3 | 3 | 인증 우회로 무단 계정 접근·개인정보 노출 가능 |
| 3 | 오류 문구 일부 잘림 (의미는 알 수 있고 인증 차단은 정상) | 3 | 1 | 3 | 같은 점수지만 2번보다 영향이 작음 |

실제로 인증 우회 결함을 발견한다면 점수 순서와 별개로 긴급 대응이 필요할 수 있습니다.

## 7. 현재 한계와 다음 작업

- 실제 URL, 빌드, 테스트 계정, API 명세를 아직 확인하지 않았습니다.
- 실행 결과, 발견한 결함, 자동화 실적은 아직 없습니다.
- 다음: 실제 테스트 환경을 확보한 뒤 TC를 실행하고 실행 증거를 추가합니다. AC-LOGIN-04-FORMAT의 TC를 작성합니다.
